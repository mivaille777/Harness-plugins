# Continuous session subscriptions

## Decision

The session service registers its live event and status listeners before awaiting durable history. Events received during that read are buffered, merged with the returned snapshot by sequence, and projected exactly once. A missing durable sequence closes the service subscription after an explicit error event.

Each subscription uses the subscribe envelope id as `subscriptionId`. The id is acknowledged in `session.subscribed`, repeated on every `agent.event`, and generated by the Lens before invoking Rust. The Lens therefore knows the accepted generation before a reader can emit and rejects events from replaced readers.

Every event carries a cursor and a persistence flag. Only successfully projected events marked persistent update the Lens recovery cursor. Transient agent status may report the latest durable cursor for context but cannot change recovery state.

The Node server disables its request idle timer after subscription acknowledgement and applies a bounded pending-write budget. Socket close disposes subscriptions that have already opened and subscriptions whose setup completes later. Rust records a lifecycle epoch before opening a reader; disconnect invalidates the epoch so a late setup cannot install a new task.

## Consequences

A reconnect can resume without losing events emitted while storage was read, and an old native reader cannot mutate the current request view. A sequence gap or write-budget overflow requires a new subscription from the last accepted cursor. Submission retry and durable request identity remain separate R03 concerns.

The Windows integration runner uses a unique named pipe, the production Node transport, and a compiled Rust probe. It does not invoke a model and does not prove browser capture or Lens window behavior.
