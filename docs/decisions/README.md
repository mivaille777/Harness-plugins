# Decision records

Use one decision record for a non-trivial change that fixes a durable choice about protocol, lifecycle, privacy, human interaction, provider support, or release behaviour. Do not use a decision record as a task checklist or a copy of implementation history.

Store records as docs/decisions/YYYY-MM-DD-short-name.md. Each record states the decision, the affected code or user behaviour, alternatives that materially differ, consequences, verification evidence, and remaining limits. Add links to the record from the pull request and the affected user or developer documentation when readers need the rule to use the product safely.

Do not edit a record to claim an unverified result. Add a follow-up record when a later decision supersedes it.
