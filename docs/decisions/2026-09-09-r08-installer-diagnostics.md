# R08.4 keeps installer checks reversible and diagnostics redacted

The development checkout is not installation evidence. The Tauri build therefore produces one current-user NSIS target, while the installer probe verifies version metadata, artifact discovery and hashes without changing system state. A separate Windows smoke installs into a unique temporary directory, launches the installed binary, repeats installation, invokes the installed uninstaller, waits for asynchronous NSIS cleanup and rejects executable residue. It neither installs a browser extension nor removes Harness user data.

Support diagnostics retain only versions, candidate identity, bridge reachability, error codes, capture phase, pause state, and counters. Material text, URLs, prompts, answers, file paths, credentials, and authorization values are redacted recursively. The current smoke proves the development account and same-version reinstall. A second clean account or VM, cross-version upgrade, missing-dependency recovery, and the complete installed product path remain separate evidence.
